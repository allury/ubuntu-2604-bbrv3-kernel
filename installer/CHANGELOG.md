# 独立安装器更新记录

## v1.2.0

- 新内核先只试启动一次。安装器把当前运行的内核保留为 GRUB 默认启动项（`GRUB_DEFAULT=saved`，写在 `/etc/default/grub.d/99-bbrv3-installer.cfg`），并用 `grub-reboot` 让下一次开机使用临时菜单项 `bbrv3-trial`。
- 临时菜单项写在 `/boot/grub/custom.cfg`，复制自新内核的普通启动项，只多了 `panic=10`，并去掉 `recordfail`。新内核崩溃或挂不上根分区时，10 秒后自动重启并回到原内核，不需要控制台，也不会停在 GRUB 菜单。
- 开机验收 `bbrv3-verify` 改为在网络就绪（`network-online.target`）后运行。全部检查通过且存在默认路由后，才把新内核设为默认启动项并删除临时菜单项；试启动失败时，回到原内核的那次开机会报告失败并清理临时菜单项。
- 以下情况不做试启动，并在安装时说明原因，行为同 v1.1.0：`/boot/grub` 位于 GRUB 无法写入的文件系统或存储层（btrfs、ZFS、LVM、软 RAID 等，判断方式与 Ubuntu 的 recordfail 一致），`GRUB_DEFAULT` 已被自定义，或使用了新参数 `--no-boot-once`。不做试启动时，会删除以前安装留下的 `99-bbrv3-installer.cfg`，让新内核按菜单顺序成为默认。
- 用本版本安装过后，后续升级请继续使用 v1.2.0 或更新的安装器：旧安装器不会移动 GRUB 保存的默认启动项，新内核不会自动成为默认。

验证范围：安装器 CI 覆盖参数解析、GRUB 菜单项解析、临时菜单项生成和试启动前提条件判断。虚拟机验收在 BIOS 引导的 Ubuntu 26.04 云镜像中验证两个场景：试启动通过后新内核成为默认启动项；故意让试启动崩溃后，虚拟机无人干预地回到原内核，且不留下待执行的一次性启动项或临时菜单项。尚未在真实 VPS 上完成重启验收，也未覆盖 UEFI 引导。

## v1.1.0

- 将 BBR 启用脚本和 sysctl 配置内嵌至安装器；运行组件全部来自同一个安装器版本。
- 保留旧内核附件的完整校验，不执行附件中的安装和启用脚本。
- 下载前检查文件总大小及可用空间；安装前按文件系统汇总保守空间预算。
- 回退内核要求同时存在非空镜像、initramfs 和 GRUB 引用；更新 GRUB 后再次检查目标及回退内核。
- 使用安装锁防止两个安装器同时修改系统；GitHub 元数据请求增加超时和重试。
- 启用 BBR 时只应用自身 sysctl 配置，不重新加载全部系统配置。

范围限制：不修改 GRUB 默认启动项，不提供无人值守启动失败回滚；GRUB 引用检查不等于实际可启动验证。内核附件下载尚无断点续传，失败后需重试。ZFS 仍按现有包契约安装并在启动后加载验证。仍需可用的服务商救援控制台。

本版本不改变内核构建、补丁、ZFS 打包和已发布内核。自动化验证覆盖脚本语法、安装选项、保护分支及空间预算，不等于在所有 VPS 上完成实机安装和重启验证。
