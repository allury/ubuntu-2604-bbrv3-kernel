# 行为验证实施清单

以下是待实现的测试计划，不是已通过的测试报告。

## 测试环境

在隔离 VM 中启动真实候选内核，使用网络命名空间构建发送端—限速路由器—接收端。netem 负责延迟、丢包与重排，瓶颈队列负责限速、排队和 ECN 标记。不要修改生产服务器 qdisc。

固定 CPU、内存、MTU、队列大小、工具版本和测试时长，保存 tc 配置与统计。延迟按双向合成 RTT 校准，避免把单向延迟误记为 RTT。记录整形位置，避免发送端整形掩盖拥塞控制差异。

同一 Ubuntu 源码上比较官方默认 BBR 与实验 BBRv3；p2 作为独立的部署回归对照。若内核基线不同，报告不得把全部差异归因于 BBR 补丁。

## 分层执行

| 层级 | 初始场景 | 验证重点 |
| --- | --- | --- |
| 正确性 | IPv4/IPv6、双向发送、并发连接、连接反复建立关闭 | 实际选用 bbr、数据长度和哈希一致、无挂起 |
| 基本网络矩阵 | RTT 2/20/100/200 ms；瓶颈 10/100/1000 Mbps | 吞吐、RTT、重传、cwnd、pacing、CPU；先做代表性组合 |
| 丢包与异常 | 随机丢包 0/0.1/1/3%；突发丢包、重排、短时断流 | 丢包恢复、恢复后继续传输、无持续零吞吐 |
| 动态网络 | 100→10→100 Mbps；RTT 20→100→20 ms | 收敛时间、排队延迟、恢复能力 |
| 竞争 | 1/4/16 条 BBR 流；BBR 与 CUBIC 共享瓶颈 | 每流吞吐、公平性、持续饥饿、队列延迟 |
| ECN | 关闭、经典 ECN 标记；适配完成后再测低延迟 ECN 接口 | 协商、ECT/CE/ECE 实际计数、重传标记、拥塞响应 |
| 长时运行 | 初始 30 分钟筛查，再 6 小时稳定性运行 | 内核警告、内存趋势、连接失败、吞吐停滞 |

测试重点是候选内核发送方向；仅从公共服务器下载文件不能充分测量本机 BBR 的发送控制行为。使用 iperf3 等可控负载，并用带内容校验的独立传输测试检测数据完整性。

## 观测与判定

- 硬性失败：panic、Oops、BUG、锁死、数据不一致、可重现连接挂起、测试环境正常但无法恢复传输。
- 保存内核日志、ss -tin、tc -s、iperf3 JSON 和场景配置；区分测试框架故障与内核故障。
- 关键场景至少重复 5 次，先测基线抖动，报告中位数及离散程度。
- 初始人工复核阈值：相同环境下吞吐中位数下降超过 10%，或延迟 p95 上升超过 20%。超过阈值暂停晋级并调查，不直接断言补丁有错，也不能自动忽略。
- 阈值应结合基线抖动、CPU 瓶颈和吞吐/延迟权衡审阅；不要求 BBRv3 在每种场景都胜过对照。
- 不同 RTT 公平性、ECN 行为、丢包恢复需要结合补丁语义审查，不能只比较一个速度数字。

## 运行与发布隔离

先通过移植审阅、完整编译、包安装和启动测试，再投入网络行为测试。短矩阵可进入后续候选版本 CI，长时测试由手动触发；固定内核和产物哈希，并保存报告。

实验阶段没有自动正式发布权限。全部证据审阅通过后，才提议将实验补丁用于下一版；不替换现有 p2 附件。
